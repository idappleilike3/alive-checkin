# 每日平安全站資安強化設計

## 目標與完成定義

本工作涵蓋每日平安正式站的會員、守護人、SOS、定位、推播、邀請、LINE 登入、金流、財務後台、管理員後台、排程與備份。安全工作以降低已知風險、建立持續偵測及可復原能力為目標，不宣稱能保證百分之百不受攻擊。

每一項只有同時具備程式或平台設定、負向測試、正常流程回歸測試及可追溯驗收證據時，才可標示完成。第 1 至 6 項是公開營運阻擋條件；第 7 至 10 項至少完成基本版本，才可進行公開測試。

## 實施策略

採分階段、風險優先的方案：

1. 先同步並鎖定 GitHub `main` 正式最新版，保留已上線的 14 天體驗、399／799 封測、提醒次數與一鍵分享流程。
2. 先完成第 1 至 6 項的機密、驗證、輸入安全、越權與資料庫權限修正。
3. 再完成第 7 至 10 項的瀏覽器安全、濫用防護、日誌、備份、監控與事故處理。
4. 每個修正使用測試驅動：先建立可重現風險的失敗測試，再做最小修正並執行完整回歸。
5. 資安修改先在獨立分支驗證；未經使用者明確同意，不直接推送 `main` 或部署正式站。

## 一、機密與供應鏈安全

- 掃描目前程式碼、可讀取的 Git 歷史、設定檔、測試資料與文件是否含真實 Token、API Key、私鑰、密碼或連線字串。
- 正式機密只能存在 Render／Vercel 等部署平台環境變數，不得進入前端、Git、日誌或錯誤回應。
- `.env`、服務帳號 JSON、資料庫匯出、備份與憑證檔必須被 `.gitignore` 排除。
- 若發現疑似真實機密，紀錄位置但不顯示值；將其列為必須由服務端撤銷及輪替的阻擋項目。
- 依賴套件固定相容版本並執行已知弱點檢查；高風險弱點未處理不得通過上線門檻。

## 二、輸入、輸出與檔案安全

- 所有 API 以伺服器端 schema 驗證型別、必要欄位、長度、枚舉、日期、電話、URL、經緯度與金額範圍。
- 所有使用者可控文字以文字節點呈現或在輸出時 HTML escape；禁止直接插入未清理的 HTML。
- SQL 或資料查詢使用參數化介面，不串接使用者輸入。
- 邀請回跳網址採同源允許清單；禁止開放重新導向及 `javascript:`、`data:` 等危險協定。
- 若有上傳功能，限制 MIME、大小、檔名及儲存路徑，不允許執行型檔案或路徑穿越。

## 三、身分驗證與工作階段

- 會員 API 驗證 LINE Login／LIFF ID token 的簽章、issuer、audience、到期時間及綁定使用者，禁止只信任前端傳入的 LINE UID。
- LINE webhook 驗證 `X-Line-Signature`；排程與內部 API 使用獨立且至少 32 bytes 的密鑰並採固定時間比較。
- 管理後台採安全 Session、CSRF、角色權限及閒置／絕對逾時；正式環境設定不足時 fail closed。
- Cookie 設 `Secure`、`HttpOnly`、`SameSite=Lax`，登入後更新工作階段並在登出時失效；若個別跨站付款回跳必須使用 Cookie，另以一次性 state 驗證，不放寬全站 Cookie。
- 高風險操作包含重新綁定 LINE、帳號重置、退款、財務修改、推播、SOS 與定位存取，必須重新檢查身分、角色與 CSRF／一次性憑證。

## 四、物件層級授權與隱私

- 每一支讀寫會員、守護關係、電話、地址、定位、平安紀錄、訂單、退款與財務資料的 API，都由伺服器依已驗證主體判斷權限。
- 禁止以請求中的 `user_id`、LINE UID、訂單號或邀請碼直接決定可存取資料。
- 守護人只取得關係有效且功能必要的最少資料；邀請尚未接受、已撤銷或已過期時不可讀取被守護人資料。
- SOS 與定位資料依事件與授權範圍限制，過期工作階段不可繼續查詢。
- 管理角色分為最高管理員、營運、財務與唯讀；財務資料與敏感會員資料依最小權限分離。

## 五、資料庫與資料保護

- 正式應用帳號不得使用資料庫擁有者／最高管理權限，只授予所需表與操作。
- 若採 Supabase，所有含會員或營運資料的表啟用 RLS，並針對會員、守護人、財務與管理員建立拒絕優先政策；服務角色密鑰僅能在後端使用。
- 敏感資料傳輸使用 HTTPS；備份與物件儲存採加密及最小權限。
- 明確盤點資料分類、保存期限與刪除／匿名化規則，定位、SOS、電話與稽核資料採較嚴格限制。
- 任何資料遷移均需可回滾、具備筆數核對且不在日誌輸出敏感內容。

## 六、瀏覽器、網路與 API 防護

- 全站 HTTP 轉 HTTPS，啟用 HSTS；設定 CSP、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Permissions-Policy` 與防點擊劫持策略。
- CSP 依 LINE LIFF、地圖、付款及實際資源建立最小允許清單，先以報告模式驗證再強制，避免破壞正式登入與分享。
- CORS 預設同源，只對確實需要的來源、方法與標頭開放，不允許含憑證的萬用來源。
- API 回應不洩漏堆疊、SQL、檔案路徑、Token、第三方完整錯誤或帳號是否存在等資訊。
- 所有寫入提供冪等或重複送出保護，特別是訂單、退款、SOS、推播及邀請接受。

## 七、頻率限制與濫用防護

- 對登入、註冊、自動補建會員、邀請建立／接受、SOS、定位、LINE 推播、金流 callback、退款、帳號重綁與排程設定獨立限制。
- 限制鍵結合可信代理後的來源、已驗證帳號與操作類型；不能只依容易偽造的標頭。
- 超限回傳一致的中文訊息及 `429`，高風險異常寫入安全事件但不記錄敏感內容。
- 對推播、SMS、影片與第三方 API 設每日成本及數量上限，避免帳號遭濫用造成費用爆增。

## 八、日誌、稽核與偵測

- 集中遮罩 LINE UID、電話、電子郵件、地址、座標、Token、Cookie、付款資料與請求本文。
- 稽核紀錄包含操作者、角色、時間、動作、目標的不可逆識別碼、結果與請求追蹤碼，不保存機密值或完整敏感資料。
- 監控登入失敗暴增、越權拒絕、SOS／推播異常、錯誤率、排程失敗、金流驗證失敗與成本異常。
- 資安事件與一般產品錯誤分流；警示內容採去識別化，只有授權角色可查看細節。

## 九、備份、復原與事故應變

- 排程產生加密備份，設定保存週期、存取權限與失敗警示；備份不可放在公開 URL。
- 定期在隔離環境執行還原演練，核對資料完整性與復原時間；只有「備份成功」但未測試還原不算完成。
- 建立事故分級、停止推播／金流／SOS 濫用的緊急開關、金鑰輪替、管理員 Session 全部失效、資料復原與使用者通知程序。
- 維護服務商、資料類別、負責人與處理時間軸，所有演練留下日期與結果。

## 十、驗證與上線門檻

- 建立資安測試組，至少覆蓋：未登入、偽造 UID、過期 Token、錯誤 audience、CSRF、角色越權、物件越權、XSS、SQL injection、開放轉址、路徑穿越、重放、頻率限制、敏感日誌與安全標頭。
- 執行原有 Python、Node／瀏覽器契約測試，確認 14 天、399／799、提醒、一鍵分享、守護綁定、SOS、推播、金流與後台未回歸。
- 正式部署後以非破壞方式確認 HTTPS、安全標頭、Cookie、未授權回應、快取與主要健康檢查。
- 後台新增資安上線狀態：每項顯示「未檢查／不通過／通過」、證據日期與備註；不得讓管理員只靠手動勾選把失敗項目標成通過。
- 任何第 1 至 6 項不通過，整體狀態顯示「禁止正式公開營運」；第 7 至 10 項未達基本門檻，顯示「禁止公開測試」。

## 不在本次範圍

- GitHub Pro 或其他付費會員不視為防駭措施。
- 不進行未經授權的外部滲透測試、流量攻擊或對真實會員資料的破壞性測試。
- 不在程式內建立或保存任何正式 Token；需要輪替的機密由服務平台管理介面處理。
- 財務損益模組依已核准的獨立設計開發，但其 API、權限、輸入與稽核必須符合本設計。

## 驗收產物

- 全站資安風險與修正清單，分級為阻擋、高、中、低。
- 自動化資安測試及完整回歸測試結果。
- 機密輪替與部署環境檢查清單，不含任何機密值。
- 備份還原紀錄與事故應變操作手冊。
- 後台資安上線狀態及稽核紀錄。
