# 會員、核心守護人與 SOS 阻斷修正設計

## 目標

修正 LINE Provider 遷移後可能出現的空白首頁、錯誤完成首次設定、守護群殘留摘要、SOS 通知不完整及智慧提醒欄位看似消失等問題。所有判斷以伺服器持久資料及 LINE 驗證結果為準，不以瀏覽器暫存或舊完成旗標取代真實綁定狀態。

## 範圍

本輪包含：

- 官方帳號好友確認與 LINE 一鍵登入
- 舊會員安全搬家後的首頁准入判斷
- 至少一位已完成 LINE 綁定的核心守護人門檻
- 核心守護人邀請、資料補齊及雙方成功通知
- 守護群每日摘要預設關閉、自訂時間與有效成員過濾
- 網頁及圖文選單統一 SOS 三擊流程
- SOS 對本人、核心守護人與有效守護群的通知結果
- SOS 誤觸取消、分級防濫用與緊急保底通道
- LINE 推播則數與預估成本稽核
- 會員說明、問與答及方案查詢的通知規則同步
- 智慧提醒在帳號搬家／方案判斷期間的清楚狀態

本輪不包含 21 天封測後台、隱私權申請、客服工單、藍新正式金流及完整資安管理後台。

## 1. 首次使用與會員恢復流程

首次使用依序執行：

1. 顯示「加入每日平安官方好友」。
2. LIFF 透過 LINE friendship 狀態確認已加入；只有按過外部連結不能視為完成。
3. 顯示「一鍵使用 LINE 登入」。
4. 後端驗證 LINE ID Token，建立新會員或尋找可搬移的舊 Provider 會員。
5. 若存在待完成的安全搬家，先完成搬家並重新載入會員資料。
6. 以「至少一位可接收 LINE 通知的已綁定核心守護人」判定首次設定完成。
7. 未達門檻時顯示核心守護人設定流程，不進入首頁，也不自動報平安。

舊的 `is_onboarding_completed`、瀏覽器 localStorage、只有姓名電話的未綁聯絡人及緊急聯絡人，均不能單獨通過首頁門檻。

## 2. 核心守護人綁定流程

未綁定會員看到不可略過的三階段流程：

1. 會員先填對方稱呼與關係，再一鍵分享綁定邀請給一位 LINE 好友。
2. 收件人先看到不需登入的邀請說明頁，內容包含邀請人、核心守護用途、會收到的通知、定位限制、解除方式與個資用途。
3. 收件人加入官方好友、由系統確認好友狀態、LINE 登入，並明確同意「雙方互相成為核心守護人」。
4. 系統以單一原子變更建立兩條互惠核心守護關係，不允許只成功一邊。

說明頁不得在使用者理解用途前直接要求登入或填寫完整個資。使用者拒絕或離開時維持 `pending`，七天後邀請自動失效，且不得通過首頁門檻。

雙向綁定完成後立即可互相接收 LINE 報平安、未報平安、SOS 與安全守護通知。姓名、電話及 Email 等完整聯絡資料不阻擋 LINE 綁定，由雙方各自在官方帳號私訊中的「完成資料」按鈕補填自己的資料；未完成時標示「聯絡資料未完整」，電話型緊急聯絡功能暫不啟用。

資料未完整時，官方帳號分別於綁定完成當下、24 小時後、第 3 天及第 7 天私訊提醒本人補填；資料完成後停止提醒，不在每次進首頁時重複跳出。

完成後：

- 雙方都收到「已互相完成核心守護人綁定」通知，包含對方姓名及「完成資料」按鈕。
- 雙方通知個別記錄成功或失敗，不因其中一方推播失敗而回滾已完成的綁定。
- 畫面清楚顯示通知結果；若對方未加官方好友，提示重新加入後補送。

## 3. 守護群摘要

- 新綁定守護群的每日摘要預設為關閉。
- 會員中心可針對每個守護群設定開關及固定發送時間。
- 發送工作只選取狀態為 active、owner 為目前會員且摘要開啟的群組。
- 摘要名單每次由目前有效會員關係重新計算，不直接沿用綁定當下的永久成員快照。
- 已解除綁定、已刪除或不再屬於該守護關係的會員不得出現在摘要。
- 群內沒有可列入摘要的有效守護會員時自動略過，不推送空摘要。
- 一般摘要設定不影響真正 SOS 的緊急通知。

## 4. 統一 SOS 流程

所有入口使用同一個永久 LIFF SOS 畫面：

- 圖文選單「需要幫忙」直接顯示 SOS 操作畫面，不先露出首頁。
- 網頁 SOS 按鈕開啟同一畫面。
- 使用者需在限定時間內連按三次；每次都有 `1/3`、`2/3`、`3/3` 畫面提示。
- 第一次點擊即開始取得本次即時位置；拒絕或逾時仍可送出不含位置的 SOS。
- 送出對象為：本人確認通知、全部有效核心守護人（不含緊急聯絡人）、目前有效且仍綁定的守護群。
- SOS 為緊急事件，不受每日摘要或一般群組提醒開關影響。
- 回應畫面列出核心守護人姓名、守護群名稱、成功數、失敗數、本人確認是否成功及失敗原因。
- 沒有任何有效核心守護人時禁止送出，直接回到核心守護人設定流程。
- 保留每日三次上限、五分鐘冷卻、定位只使用本次請求座標及完整通知稽核紀錄。

## 4.1 報平安入口的守護人門檻

圖文選單、首頁按鈕與 LINE 聊天室的「報平安」使用相同門檻：

- 已有至少一位有效核心守護人時，才可執行報平安並顯示「今日已平安」。
- 尚未綁定時不得建立簽到紀錄，必須顯示「尚未完成核心守護人綁定」。
- 阻擋畫面提供「立即邀請核心守護人」、「核心守護人會做什麼？」及「稍後再設定」。
- 「稍後再設定」只關閉畫面，不能繞過門檻完成報平安。
- 綁定完成後詢問「要立即回報今日平安嗎？」，由會員確認後才建立簽到。

## 4.2 SOS 誤觸取消與分級防濫用

SOS 是安全功能，不因單次誤觸直接完全停用三天。系統以事件紀錄、冷卻、觀察期及人工審核逐級處理，並保留真正緊急時的最低求救能力。

- SOS 送出後提供「誤觸／我已安全」按鈕。會員確認後，系統建立取消事件，並立即向原事件中實際通知成功的本人、核心守護人及守護群補送取消警報；不得通知未收到原 SOS 的對象。
- 原 SOS 與取消通知分別記錄實際送達人數、失敗人數、LINE 訊息則數及推播成本分類，不刪除原事件。
- 保留五分鐘冷卻及每日三次 SOS 上限。重試只處理上一輪失敗的收件人，不可向已成功收件者重複推播。
- 同一會員在連續 24 小時內確認誤觸達兩次，進入三天觀察期。觀察期不是完全封鎖；再次發送時必須長按確認並選擇或填寫簡短原因。
- 會員在七天內於觀察期再次多次誤觸、重複觸發冷卻或出現其他異常模式時，後台標記為「疑似濫用」，自動限制一般 SOS 群發七天並等待管理員審核。
- 疑似濫用期間仍顯示撥打 110／119，並允許向一位主要核心守護人發送單一緊急通知。沒有主要核心守護人時顯示電話求助及重新設定核心守護人，不得假裝通知成功。
- 管理員可查看事件時間、誤觸取消、收件人數、失敗原因及限制依據，並可解除限制或確認延長；不可在沒有稽核理由下永久封鎖。
- 介面不得使用羞辱性「亂按」文案，統一使用「誤觸」、「重複測試」及「疑似濫用」。

## 4.3 LINE 訊息用量與成本稽核

- 每次 LINE 主動推播以實際接收人數記錄訊息則數；群組推播依群內實際接收人數計算，不把一個群組誤算成一則。
- 分類統計智慧提醒、報平安、未報平安、SOS、SOS 取消、守護群摘要及綁定通知。
- 後台顯示本月已使用則數、各類占比、每位會員用量、誤觸造成的用量及依目前速度推估的月底用量。
- 用量達後台設定額度的 70% 與 90% 時顯示警示；SOS 與安全通知優先於一般智慧提醒及摘要。
- 智慧提醒預設只私訊本人，每位會員每日最多兩則；同一時段的多項提醒合併為一則。通知核心守護人每日最多一則，守護群同步預設關閉。
- SOS 不占智慧提醒的每日兩則上限，但仍計入 LINE 官方帳號的實際訊息用量。

## 5. 智慧提醒

- 智慧提醒表單不得從 DOM 移除。
- 有 799 權限的會員正常顯示新增、編輯及儲存欄位。
- 安全搬家尚未完成或方案資料仍在恢復時，顯示「會員資料恢復中，完成後會自動恢復智慧提醒」，不可誤顯示成免費方案升級。
- 確認不是 799 方案時才顯示方案限制說明。
- 儲存按鈕及主要欄位在手機視窗中必須可見、可捲動及可操作。
- 會員畫面顯示「今日智慧提醒已使用 X／2 則」；相同時段的提醒合併傳送。
- 智慧提醒收件方式提供「只通知自己（預設）」及「通知一位指定核心守護人」；指定核心守護人每日最多一則。智慧提醒不提供守護群同步，避免隱私外洩及大量消耗 LINE 訊息額度。

## 5.1 會員說明、問與答及方案查詢

- 會員說明與問與答必須解釋 SOS 的正確使用情境、三擊確認、誤觸取消、冷卻、每日上限、觀察期、疑似濫用限制及限制期間的 110／119 與主要核心守護人保底通道。
- 說明 LINE 私訊、核心守護人、緊急聯絡人及守護群的通知差異，不得暗示只有電話資料的緊急聯絡人會收到 LINE 推播。
- 智慧提醒說明標示預設只私訊本人、每日兩則、同時段合併及其 LINE 訊息額度影響。
- 方案頁與完整比較表同步列出各方案可用的提醒次數、核心守護人數、守護群功能及 SOS 防濫用規則。SOS 的基本求救能力不得因付費等級而消失。
- 會員可從會員中心及問與答直接開啟方案查詢，不需返回首頁；方案頁返回時保留原會員流程位置。

## 6. 資料與安全約束

- 所有會員身分以後端驗證後的 LINE user ID 為準。
- 不信任前端傳入的其他會員 ID、方案、綁定完成旗標或群組 owner。
- Provider 搬家進行中不得建立互相競爭的空白會員狀態。
- 守護人、群組及 SOS 收件人必須在送出當下重新授權與過濾。
- 不在回應、日誌或前端暴露 access token、ID token、完整遷移密鑰或不必要的完整 LINE user ID。
- 所有資料變更使用既有的原子狀態寫入與失敗稽核機制。

## 7. 驗收條件

- 未加官方好友：停在加入好友步驟。
- 已加好友但未登入：停在 LINE 登入步驟。
- 登入後找到舊會員：先搬家，原方案、聯絡人、提醒與紀錄仍存在。
- 登入後沒有已綁核心守護人：一定顯示分享及綁定流程，不進首頁。
- 只有緊急聯絡人或未綁聯絡人：仍視為未完成。
- 核心守護人完成綁定：雙方收到成功通知且首頁解鎖。
- 收件人先看到完整用途說明，再加入好友、登入並同意雙向互相守護。
- 雙向關係不可只建立一邊；雙方立即可收 LINE 通知，完整資料透過私訊稍後補填。
- 圖文選單、首頁及聊天室報平安在未綁定時均不寫入簽到，只顯示邀請提醒。
- 解除關係的會員不再出現在守護群摘要。
- 摘要預設關閉；開啟後只在會員指定時間發送一次。
- 兩個 SOS 入口都直接呈現三擊畫面。
- 三擊後本人、所有有效核心守護人與有效守護群收到通知，畫面顯示逐類結果。
- SOS 誤觸取消只通知原事件實際成功收件者，且原事件及取消事件均保留稽核與訊息則數。
- 24 小時內兩次誤觸會進入三天觀察期，但不完全封鎖緊急求救。
- 疑似濫用限制期間仍提供 110／119 與一位主要核心守護人的保底通知。
- 後台能按類型、會員及月份查詢 LINE 訊息用量，並顯示 70%／90% 警示與月底預估。
- 會員說明、問與答及方案比較表與實際 SOS、智慧提醒及通知規則一致。
- 799 搬家完成後智慧提醒表單與既有資料恢復顯示。
- 完整自動測試、產品規則、敏感資料掃描、程式複審及 LINE 雙帳號實測通過後才可部署。
