# 必要服務費用監控設計

## 目標

在既有「財務與必要支出」頁內管理會影響每日平安營運的外部服務，讓管理者看見費用、付款期限、付款狀態、服務風險與直接付款網址。Render PostgreSQL 先登記為待加值，不執行扣款；接近期限後由管理者進入 Render 完成升級。

## 本次範圍

- 新增必要服務資料模型，與已發生的會計支出分開，避免尚未付款就計入本月損益。
- 必要服務欄位：名稱、供應商、分類、重要程度、付款狀態、計費週期、原幣金額、台幣預算、付款期限、下次續費日、付款網址、風險說明、備註與提醒天數。
- 支援「待付款、即將到期、已付款、逾期、可暫停」狀態；最高風險項目在期限逼近或逾期時顯示紅色警示。
- 顯示未來應付款項與 30／14／7／3／1 天提醒節點；已過的節點標為已錯過，不重複發送。
- 新增、更新必要服務時保留財務稽核紀錄。
- 預先建立 Render PostgreSQL：`alive-checkin-state`、期限 `2026-08-23`、Basic-256mb US$6 + 1 GB 儲存 US$0.30、合計 US$6.30/月、台幣預算 NT$210/月與 NT$2,500/年、待加值、最高風險，以及 Render 專屬方案網址。

## 資料與計算規則

- 尚未付款的必要服務不計入 `expenses`，因此不影響現金損益。
- 付款後可將服務標為已付款，並由管理者另建立正式支出紀錄；本次不自動產生會計支出，避免重複入帳。
- 必要服務持久化欄位包含 `category`、`billing_cycle`（`monthly`／`yearly`／`one_time`）、`currency`、`original_amount` 與 `next_renewal_on`；`original_amount` 是該服務依 `billing_cycle` 每一計費期的 `currency` 原幣金額，`monthly_twd` 則是不抓即時匯率的台幣月預算。
- `category` 沿用財務模組既有允許分類；幣別為三碼英文字母，日期為台灣日曆的 `YYYY-MM-DD`。舊版 `monthly_usd`／`annual_twd` 資料仍可載入並回填新欄位。
- 台幣金額採預算值，不即時抓匯率；Render 實際刷卡金額以帳單為準。
- 一般服務的年預算只能由月預算乘 12 產生，不接受不一致的輸入；Render 以明確的 `annual_budget_override: 2500` 保留已核准的 NT$210/月、NT$2,500/年保守預算。
- Render 尚未開始正式月繳，初始 `next_renewal_on` 與本次加值期限同為 `2026-08-23`，代表下一個必須處理的付款日期；啟用後可由管理者改成實際續費日。
- 距離期限的天數依台灣日期計算；期限當天為 0 天。
- 每次回傳都依期限確定性產生不重複的提醒節點紀錄：未到、今天提醒、已錯過或已停止；已過且未付款的節點顯示「已錯過」，已付款後所有節點停止且不顯示持續警示。本功能不送出 LINE 訊息。

## 介面

- 在現有財務頁上方新增「必要服務監控」區塊。
- 在管理員的「會員管理」頁最上方新增必要服務到期摘要；只對管理員顯示，不出現在一般會員中心。
- 期限進入 30／14／7／3／1 天節點時顯示醒目警示，其中最高風險服務使用紅色；已付款後解除警示。
- 每列顯示服務、費用、期限、剩餘天數、狀態、風險與「前往付款」按鈕。
- 付款網址只允許 `https://`，並以新分頁開啟。
- 提供新增／編輯表單；只有 `finance.manage` 權限可儲存。
- Render 項目清楚顯示「現在不扣款，接近期限再加值」。

## API 與安全

- `GET /api/admin/finance/dashboard` 回傳 `essential_services` 與摘要。
- 第一次 dashboard GET 在既有狀態交易鎖內建立並持久化 Render 預設資料，寫入 `created_at` 與唯一一筆 `essential_service.create` 稽核；重複 GET 不新增種子或重複稽核。
- 管理員會員頁沿用相同 dashboard 資料呈現到期摘要，不另建一份服務資料。
- `POST /api/admin/finance/services` 新增服務。
- `PUT /api/admin/finance/services/{id}` 更新狀態或資料。
- 沿用既有管理員登入、CSRF 與 `finance.manage` 權限。
- 驗證日期、金額、狀態、分類、提醒天數與 HTTPS 付款網址；不保存信用卡或 Render 登入資料。
- dashboard 與必要服務 API 一律傳入 `current_app_time(config)`，避免 Render 主機時區影響台灣日期與到期天數。

## 不在本次範圍

- 不替使用者按 Render 的 `Save Changes`，不產生扣款。
- 不建立新資料庫、不修改 `DATABASE_URL`。
- 不保存信用卡資訊。
- 不假設後台頁面本身能在瀏覽器關閉時推播；2026-08-16 與 2026-08-20 的外部提醒沿用已建立的排程提醒。
