# SOS 協作回覆與守護群返回設計

日期：2026-07-31  
狀態：使用者已核定互動規則，待書面規格確認

## 目標

將圖文選單與網頁的「需要幫忙」統一到同一套 SOS 流程，讓求助者、核心守護人與守護群看到一致的即時狀態；同時修正守護群設定頁的返回行為，避免完成設定後固定跳回首頁。

## SOS 送出流程

1. 圖文選單與網頁按鈕都開啟首頁既有的 SOS 視窗，不建立第二套獨立流程。
2. 第一次按下時開始取得定位，第二次繼續確認，第三次才送出。
3. 有定位時附上 Google 地圖連結；定位逾時或失敗時清楚提示，並允許使用者確認改送不含定位的 SOS。
4. 只有 1 位有效核心守護人時直接通知該守護人。
5. 有 2～5 位有效核心守護人時，依後台通報優先順位顯示勾選清單；使用者可選擇本次通知對象。
6. 一次最多通知 5 位核心守護人。守護群同步通知不占這 5 位名額。
7. 所有已啟用的有效守護群同步收到 SOS。

## 守護人 Flex 卡片

每位核心守護人與守護群收到同一事件的 Flex 卡片，包含：

- 🟢「我來聯繫」：第一位按下者成為主要接手人；後續按下者可列為協助者。停止尚未送出的守護人催促，所有參與者同步看到已有人接手。
- 🟡「請其他人聯繫」：此人暫時不負責，但仍保留事件查看與後續狀態通知。
- 🔴「我無法處理」：記錄此人無法協助，停止對此人的後續提醒，但仍保留稽核紀錄。
- 🔵「已找到本人」：直接結束事件，記錄結案人與時間，向本人、所有已通知守護人及守護群同步結案。

若所有已通知核心守護人都選擇黃色或紅色，且無人選擇綠色，事件保持未結案並立即同步「目前尚無守護人接手」給本人、守護人與守護群。

## 事件狀態與同步

單一 SOS 事件保存：

- 事件編號、本人、建立與送出時間
- 定位座標、定位時間與 Google 地圖連結（若取得）
- 本次選取的核心守護人、順位、個別送達結果
- 守護群送達結果
- 每位參與者的最新回覆與時間
- 主要接手人、協助者、是否無人接手
- 事件狀態：已送出、有人接手、尚無人接手、已找到本人、本人確認安全
- 完整時間軸

本人網頁以既有狀態 API 輪詢更新；每次守護人回覆後，後端向本人、所有已通知核心守護人及守護群推送最新狀態。任何回覆都必須驗證回覆者確實屬於該事件的收件人或守護群成員，避免外部人員操作。

重複按下同一動作採冪等處理，不重複新增時間軸或重複推播。已結案事件不得再改回處理中。

## 後台事件中心

後台新增或擴充 SOS 完整事件詳情：

- 本人與事件目前狀態
- 定位與 Google 地圖入口
- 核心守護人、守護群的送達狀態
- 每位收件人的回覆、角色與時間
- 無人接手警示
- 按時間排序的事件時間軸
- 結案人、結案方式與結案時間

後台只顯示營運處理需要的資料；一般會員狀態 API 不回傳其他人的 LINE user ID。

## 守護群設定返回

守護群設定頁新增明確的「返回上一頁」按鈕：

1. 優先返回開啟設定頁前的站內頁面。
2. 若瀏覽器沒有可安全返回的站內上一頁，導向 LIFF 會員中心 `?open=member`。
3. 不再以首頁作為固定返回目的地。

頁面載入時保存安全的站內返回來源；不接受外部網址作為返回目標，避免開放式跳轉。

## 測試與驗收

採測試先行，至少覆蓋：

- 第三次按下才送出，以及第一次按下即開始定位
- 1 位守護人直接通知；2～5 位依順位勾選；核心守護人最多 5 位
- 守護群不占 5 人名額
- 四種 Flex 動作的狀態轉移、權限與冪等
- 全部黃色／紅色時產生無人接手警示
- 藍色結案後禁止再變更
- 本人、守護人、守護群同步的收件範圍
- 後台完整時間軸與一般會員資料去識別
- 守護群設定返回上一頁，以及無上一頁時回會員中心
- 既有 SOS、提醒、會員中心與守護群測試全部通過

## 不在本次範圍

- 不新增 SMS 或電話通報
- 不修改方案價格或守護人名額
- 不建立第二套 SOS 頁面
- 不加入軌跡回放或背景持續定位
