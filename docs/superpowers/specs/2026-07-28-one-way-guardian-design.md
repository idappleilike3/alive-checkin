# 單向核心守護與 14 天體驗設計

## 目標

把「替別人接收通知」與「自己使用報平安」拆成兩項獨立權益，避免接受邀請後免費取得雙向服務。

## 正式規則

- A 有 14 天體驗或有效付費方案，邀請 B 成為核心守護人。
- B 加入「每日平安」官方 LINE、LINE 登入、填寫自己的姓名／與 A 的關係／手機並同意後，建立單向關係「B 守護 A」。
- B 可免費收到 A 的報平安、逾時預警、SOS 與安全守護通知。
- B 只接受邀請時不啟用自己的 14 天體驗，也不能使用「我平安」對外發送服務。
- B 若點「我也要報平安」，系統才明確開通 B 自己的一次性 14 天體驗，並引導 B 分享新邀請給自己的核心守護人。
- 若 B 邀請 A，A 必須重新登入、填寫資料並同意，才建立第二筆「A 守護 B」。不得用 `mutual_core` 或其他舊欄位跳過第二次同意。

## 頁面與按鈕

- 邀請頁：提供加入官方 LINE、LINE 登入、四步驟說明與接受邀請入口。
- 首頁：一般會員顯示一鍵分享、守護人資料／狀態及會員中心入口。
- 守護人接收模式：顯示「你正在免費守護誰」，主要按鈕為「我也要報平安｜免費體驗 14 天」。
- 綁定成功視窗：說明目前只完成單向守護，提供「完成」與「我也要報平安」兩個選擇。
- 會員中心：分開顯示「守護我的人」與「我正在守護的人」，並顯示等待加入、等待接受、已完成。

## 資料與權益

- 每一方向保存一筆獨立關係。
- `guarding_for` 只代表接收對方通知，不代表擁有試用或付費權益。
- 報平安、提醒、定位與 SOS 主動服務繼續由被守護者本人的有效會員權益判斷。
- 反向邀請不得自動建立、不得自動扣款。

## 驗證

- 回歸測試確認接受邀請不啟用 B 的 trial。
- 回歸測試確認舊 `mutual_core=true` 仍只建立一個方向。
- UI 測試確認邀請參數在 LINE 登入後保留、表單會重新出現。
- UI 測試確認「我也要報平安」明確導向 14 天體驗，不以接受邀請直接解鎖。
