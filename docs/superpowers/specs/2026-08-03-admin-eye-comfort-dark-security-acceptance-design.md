# 管理後台護眼暗色與資安 10 項實際驗收設計

## 目標

將每日平安管理後台所有頁面統一改為固定護眼暗色，同時延續既有全站資安強化設計，讓資安 10 項只能依自動檢查或正式平台證據判定，不得以人工勾選偽造通過。

## 已核准的視覺方案

- 採固定暗色，不新增亮／暗切換開關。
- 頁面主背景使用深灰藍，卡片與表格使用稍亮的深灰，文字使用柔和米白；避免純黑背景配純白文字。
- 登入區、側欄、所有功能頁、財務、資安、彈窗、表格、輸入框、下拉選單、文字區、圖文卡編輯器及行動版導覽全部納入。
- 成功、警告、錯誤仍使用綠、琥珀、紅三種語意色，但降低大面積高亮背景；文字與互動元件需維持清楚對比。
- 不改後台資訊架構、資料、功能、權限、API 或既有流程。
- 原本 LINE 圖文卡的白底預覽可保留，因該區是在模擬使用者實際收到的卡片；預覽外框與編輯控制區仍改成暗色。

## 暗色實作邊界

以 `admin.html` 的 CSS 自訂屬性作為唯一色彩來源，新增背景、表面、邊框、主文字、次文字、輸入框、焦點、成功、警告與錯誤變數。既有散落的亮色宣告以同一組變數覆蓋或替換，不複製第二套頁面。

驗收需覆蓋：

1. `body`、主要面板與側欄不再使用白色或接近白色的大面積背景。
2. 表格表頭、表身、橫向捲動容器與展開明細在暗色下可讀。
3. `input`、`select`、`textarea`、checkbox、disabled、focus-visible 與瀏覽器自動填入不產生刺眼白塊。
4. 登入狀態、儲存提示、錯誤提示、徽章與發布狀態仍可依顏色及文字辨識。
5. 手機側欄、遮罩與彈窗不出現未覆蓋的亮色區塊。
6. 既有後台行為測試全部維持通過。

## 資安 10 項實際驗收模型

沿用 `2026-08-03-full-site-security-hardening-design.md` 的十個領域及阻擋規則。本次不把任何狀態直接改成通過，而是為每項輸出以下資料：

- `status`：`passed`、`failed` 或 `not_checked`
- `checked_at`：證據實際產生時間；沒有證據時為空
- `evidence_source`：自動測試、正式 HTTP 探針、GitHub／依賴掃描、Render／Postgres 設定、備份還原紀錄或事故演練紀錄
- `evidence`：不含機密值的中文摘要
- `blocking`：阻擋正式營運或公開測試
- `remediation`：未通過時的下一個明確動作

狀態只能由以下來源產生：

1. 可重跑且成功的程式測試或正式站非破壞探針。
2. 具日期與結果的正式平台設定證據。
3. 具日期、範圍、結果及負責人的備份還原或事故演練紀錄。

單純存在環境旗標、管理員手動勾選或沒有日期的文字聲明，不足以判定 `passed`。若本工作環境無法讀取 Render、Postgres、告警收件結果、金鑰平台或備份內容，該項維持 `not_checked`，並在後台顯示需要使用者或平台補充的證據，不假報完成。

## 十項證據要求

1. 機密與供應鏈：Git 工作樹與可檢查歷史未發現機密、忽略規則有效、正式必要機密僅驗證存在與長度、不得回傳值。
2. 輸入、輸出與檔案：XSS、危險 URL、路徑穿越、錯誤輸出與金額／日期邊界負向測試通過。
3. 身分驗證與工作階段：未登入、逾時、CSRF、Cookie、LINE／排程驗證與正式 fail-closed 測試通過。
4. 物件授權與隱私：角色越權及跨會員／跨訂單／跨守護關係存取測試通過。
5. 資料庫與資料保護：正式資料庫使用非擁有者帳號或等效最小權限的可查驗證據；傳輸與備份加密證據存在。
6. 瀏覽器、網路與 API：正式 HTTPS、HSTS、CSP、nosniff、Referrer-Policy、Permissions-Policy、後台 no-store 與未授權回應探針通過。
7. 頻率限制與濫用：登入、推播、SOS、邀請、重新綁定及高成本通道限制的負向測試通過。
8. 日誌、稽核與偵測：敏感值遮罩測試通過，且正式告警已用不含會員敏感資料的測試事件確認收件。
9. 備份、復原與事故應變：最近一次加密備份與隔離還原演練均有日期、結果、筆數核對及復原時間；事故手冊已演練。
10. 驗證與上線門檻：固定版本依賴弱點掃描無未處理高風險弱點，關鍵回歸與正式啟動／健康探針通過。

## 顯示與權限

- 資安頁顯示整體結論、10 項狀態、證據來源、檢查時間、摘要與修正動作。
- `passed` 顯示「通過」，`failed` 顯示「未通過」，`not_checked` 顯示「未檢查」，不得把後兩者合併。
- 未登入仍回傳 `401`；沒有 `system.manage` 的角色回傳 `403`。
- 頁面不得提供「設為通過」按鈕，也不得接受任意前端狀態寫入。
- 第 1 至 6 項任一未通過或未檢查，整體顯示禁止正式公開營運；第 7 至 10 項任一未通過或未檢查，顯示禁止公開測試。

## 測試與部署門檻

- 暗色 CSS 契約測試須先失敗，再完成實作並通過。
- 資安狀態模型、三態顯示、權限、證據欄位與阻擋邏輯須有 Python 與 Node 測試。
- 使用 Python 3.11 正式依賴執行語法、資安／後台重點測試與 Gunicorn `/health` 探針。
- 執行完整前端行為測試，並使用專案離線入口執行 Python 回歸，禁止測試連到正式 LINE API。
- 部署前再次同步 `origin/main` 並安全整合；不得覆蓋等待期間的新功能。
- 部署後驗收正式 `/health`、後台暗色標記、資安 API 權限及安全標頭。只有具有證據的項目可回報通過，其他項目列出阻擋原因。

## 不在本次範圍

- 不進行破壞性滲透測試、流量攻擊、真實付款、真實 SOS 或對正式會員發送 LINE 測試訊息。
- 不讀取、顯示、下載或提交正式機密值。
- 不為了得到全綠結果而降低安全門檻或刪除既有測試。
