# LINE 半自動實機驗收設計

## 目標

在管理後台追蹤封測者的 LINE 私訊、799 家庭群、SOS、取消、重試、濫用封鎖及群組成員異動驗收。系統保存可核對的發送結果，管理員以測試手機確認實際收到與畫面正確後，才能標記通過。

## 安全界線

- 驗收工具不得接受任意 LINE ID 或群組 ID 後直接發送。
- 驗收對象必須是目前 21 天封測名單中的會員。
- 系統證據只能關聯既有通知、SOS、守護群及 webhook 紀錄。
- 人工結果只有 `pending`、`passed`、`failed`，並保留確認時間與簡短備註。
- 所有讀寫 API 均使用既有管理員工作階段；寫入另外要求 CSRF。
- 後台不顯示完整敏感識別碼，API 回應只提供遮罩識別碼。

## 驗收項目

固定七類：`direct_message`、`family_group`、`sos`、`sos_cancel`、`sos_retry`、`abuse_block`、`group_member_change`。B399 不要求家庭群相關項目；A 與 B799 要求全部七項。

## 資料與流程

`line_acceptance_cases` 保存每位封測者、驗收類型、系統證據狀態、人工確認狀態、備註與時間。建立案件時由後端從現有紀錄計算系統狀態，不由前端宣稱成功。後台列表顯示各組通過率與待確認項目。

## 錯誤處理與測試

非封測會員、未知類型、過長備註及不存在案件均拒絕。測試涵蓋資料驗證、證據關聯、遮罩、權限、CSRF、XSS 安全渲染，以及完整離線回歸；測試不得連到 LINE 或其他外網。
